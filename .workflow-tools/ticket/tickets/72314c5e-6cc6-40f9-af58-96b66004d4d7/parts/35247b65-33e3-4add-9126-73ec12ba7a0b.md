## Problem

Renaming a worktree and branch currently requires agents to hand-run `mv .worktrees/<old> .worktrees/<new>`, `git worktree repair .worktrees/<new>`, and `git branch -m agent/<old> agent/<new>` from the repository root. `git worktree move` is unusable because the worktree contains five submodules.

## Acceptance Criteria

1. `worktree-ctl` exposes `rename <old-name> <new-name>` using the verified move, top-level repair, and branch-rename sequence.
2. The command refuses when the shell working directory is inside the worktree being renamed.
3. The command refuses a dirty worktree unless a documented force option is supplied.
4. After rename, the command verifies all five submodules remain populated and repairs any unpopulated submodule.
5. `--dry-run` reports the complete operation without mutation, consistent with other lifecycle commands.
6. The currently failing rename cases in `tools/worktree/tests/run.sh` pass.
7. Tests cover success, inside-worktree refusal, dirty-worktree refusal, force behavior, submodule verification, and dry run.

This ticket depends on the Rust worktree-tooling rewrite that will host the command.
