## Acceptance Criteria

1. Populating a worktree submodule does not write `core.worktree` into any shared `.git/modules/<name>/config`. A regression test creates a worktree, populates all five submodules (`memory-viewers`, `context-stack`, `memory-api`, `viewer-api`, and `memory-kernel`), and asserts the key is absent from every shared config.
2. Removing a populated worktree directory with plain `rm -rf` outside Git leaves the main checkout usable. A regression test manually deletes the worktree directory and asserts root `git status` succeeds with no `fatal:` output.
3. Recovery is available without hand-editing Git internals. The supported recovery unsets `core.worktree` for affected submodules and prunes the submodule and root worktree registrations.
4. `worktree.sh doctor` and successor `worktree-ctl doctor` inspect `core.worktree` in `.git/modules/<name>/config` for each of the five submodules, resolving each value relative to `.git/modules/<name>/`. `doctor` classifies a missing resolved path as `DANGLING` (blocking), an existing path inside `.worktrees/` rather than `<repo-root>/<name>` as `HIJACKED`, and an absent key or a value resolving to `<repo-root>/<name>` as `OK`. The relative value `../../../<name>` is correct and must not be reported as broken. `doctor` exits non-zero for any `DANGLING` result, prints `git config --file .git/modules/<name>/config --unset core.worktree` for each affected submodule, and provides or documents a `--fix` path that unsets the key then prunes. `doctor` also flags stale `.git/modules/<name>/worktrees/<entry>` registrations whose `gitdir` target is missing.
