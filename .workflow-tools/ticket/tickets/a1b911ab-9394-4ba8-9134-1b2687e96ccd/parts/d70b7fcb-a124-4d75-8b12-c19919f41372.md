## Existing test assets (surveyed before writing anything new)

Two harnesses already exist. Neither needs to be invented.

### 1. `tools/worktree/tests/` — shell suite over `worktree.sh`

`common.sh:fixture_repo()` already builds a genuine throwaway repo in `mktemp -d`:
a real submodule source repo, a real superproject that `submodule add`s it, and a
copy of `worktree.sh` committed into it. Every test gets an isolated repo with
real git topology. This is the right home for lifecycle behavior.

Baseline as of `a936c87f` — **6 pass, 10 fail**:

The failures are not flaky. They are unimplemented contracts: `worktree.sh`
exposes `new | list | rebase | merge | remove | doctor` and has no `rename`,
no `finish`, and no dirty-refusal in `remove`. Six of the ten red tests
describe exactly the lifecycle rules this ticket specifies, written before the
behavior existed.

### 2. `memory-api/crates/memory-fixtures` — Rust fixture loader

Self-described as a "Shared E2E fixture loader for multi-store and multi-worktree
memory tests". Already provides `materialize_git_fixture()` (real git repo plus
real submodules in a tempdir), `seed_session_store()`, and `git_has_changes()`.
`WorktreeDef` carries a `kind` field whose only recognized value today is
`"submodule"` — that field is the extension point for a `"linked"` kind
representing a `.worktrees/<name>` entry.

This is the right home for resolver-level tests (AC 1–5): discovery, glob vs
scan, ambiguity, caching, hard-fail.

### Split

- Resolution semantics (AC 1–5, 7) → Rust, `memory-fixtures` + resolver tests.
- Worktree lifecycle (AC 6, 8–12) → shell, `tools/worktree/tests/`.

### Incidental finding — AC 7

A freshly created worktree cannot serve entity-store traffic. Its `.ticket`
carries the tracked payload (`tickets/`, `index.toon`, `workspace-policy.toml`)
but not the gitignored machine-local index (`tickets.db`, `search_index/`), and
the store refuses to open: `workspace not initialized ... run the 'init'
command`. Reproduced on this session's own worktree; resolved with
`ticket init && ticket scan` (1518 tickets integrated). Worktree creation and
recycling must both rebuild these indexes, or every newly routed session fails
its first store call.
