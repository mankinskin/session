## Decisions (interview, 2026-08-07)

### 1. The red shell suite is aspirational, not authoritative

`worktree.sh` is to be **rewritten as a Rust binary**, with its tests written in
Rust driving git through a library rather than shelling out. The existing
`tools/worktree/tests/*.sh` suite is therefore not a spec to satisfy in place —
it is prior art whose *intent* carries over to the Rust tests. The shell suite
and its harness retire with the script.

Consequence: the earlier deletion of `test_rename_updates_session_anchor.sh`
needs no restoration, since the whole shell suite is being replaced. Its
intent — a rename must re-point the session's anchor — must survive as a Rust
test case.

### 2. Reuse is rename/move in place, gated on cleanliness

- **Clean worktree**: rename/move in place and re-point the branch
  automatically, from the hook, with no human in the loop. Preserves the built
  `target/` directory and the rebuilt entity-store indexes, avoiding a full
  rebuild (~2m26s here) and a re-scan of 1518 tickets.
- **Dirty worktree**: never repurposed automatically. Repurposing requires an
  explicit agent decision, framed as re-topicing the worktree.

### 3. Scope split

This ticket keeps **resolver discovery only** — AC 1–5 and AC 7. Session
`session_id` resolves to its worktree via glob-then-scan, with caching,
ambiguity as a named error, and hard-fail on no match.

The worktree **lifecycle and recycling** work — the Rust rewrite of
`worktree.sh`, eager creation in the `UserPromptSubmit` hook, locking while
active, and clean/dirty-gated reclamation — moves to a follow-up ticket on its
own branch.

Rationale for the split: discovery alone fixes routing for worktrees created by
hand, which is the situation today, and is independently shippable.
